# Dialog Spy Bot 🕵️

**Dialog Spy Bot** — это Telegram-бот для отслеживания изменений и удалений сообщений в ваших личных чатах через Telegram Business API. Бот работает по принципу "нулевого хранения" — не сохраняет сообщения надолго, а уведомления отправляет только в ваш личный чат с ботом.

## 🚀 Возможности

- ✅ **Отслеживание изменений сообщений** — получайте уведомления о редактированных сообщениях с показом старого и нового текста.
- ✅ **Отслеживание удаленных сообщений** — узнавайте, какие сообщения были удалены из ваших чатов.
- ✅ **Сохранение медиафайлов** — удаленные фото, видео, голосовые и видеосообщения временно сохраняются в вашем S3-совместимом хранилище.
- ✅ **Умное получение медиа** — команда `/get_latest_media` всегда отдает именно тот файл, о котором шла речь в последнем уведомлении.
- ✅ **Краткосрочное хранение** — сообщения кэшируются в Redis на 2 минуты. Медиафайлы в S3 также удаляются автоматически.
- ✅ **Безопасность** — принцип stateless, никакие данные не сохраняются надолго.
- ✅ **Форматированные уведомления** — красивые уведомления с поддержкой Markdown.
- ✅ **Централизованное логирование** — подробные логи с временными метками для отладки.

## 🛠️ Технический стек

- **Runtime:** Bun
- **Язык:** TypeScript
- **Framework:** Telegraf.js
- **API:** Telegram Business API
- **Кэширование:** Redis
- **Хранение файлов:** S3-совместимое хранилище (Yandex Object Storage, Selectel, MinIO и др.)

## 📋 Требования

1. **Telegram Premium** подписка (для доступа к Telegram Business).
2. **Redis** сервер.
3. **S3-совместимое хранилище** и его учетные данные.
4. **Bun** v1.0.0 или выше.
5. **Node.js** (для совместимости с некоторыми пакетами).

## ⚙️ Установка и настройка

### 1. Клонирование репозитория

```bash
git clone <your-repository-url>
cd dialog-spy-bot
```

### 2. Установка зависимостей

```bash
bun install
```

### 3. Настройка переменных окружения

Создайте файл `.env` в корне проекта, скопировав `.env.example`:

```bash
cp env.example .env
```

Отредактируйте файл `.env`, указав **все** необходимые параметры:

```env
# Токен вашего Telegram бота (получите у @BotFather)
BOT_TOKEN=

# ID владельца бота (ваш Telegram ID, получите у @userinfobot)
OWNER_ID=

# URL для подключения к Redis
REDIS_URL=redis://localhost:6379

# Время жизни кэша сообщений в Redis (в секундах, по умолчанию 120)
CACHE_TTL=120

# --- Настройки S3-совместимого хранилища ---
# Имя бакета
S3_BUCKET=
# Регион
S3_REGION=
# Endpoint URL
S3_ENDPOINT=
# Ключ доступа (Access Key)
S3_KEY=
# Секретный ключ (Secret Key)
S3_SECRET=

# Режим разработки (true/false) - включает дополнительное логирование событий
DEV_MODE=false
```

### 4. Запуск с Docker Compose (Рекомендуемый способ)

Docker Compose — самый простой способ запустить бота и Redis сервер вместе.

1.  Убедитесь, что у вас установлен Docker и Docker Compose.
2.  Заполните файл `.env` вашими данными.
3.  Выполните команду:

```bash
docker-compose up -d
```

**Управление контейнерами:**

- `docker-compose logs -f app` — просмотр логов бота.
- `docker-compose down` — остановка и удаление контейнеров.

**Структура Docker:**

- `redis` - Redis сервер для кэширования.
- `app` - Приложение Dialog Spy Bot, которое подключается к Redis.

### 5. Запуск без Docker

Если вы хотите запустить бота локально без Docker, убедитесь, что у вас есть доступный Redis сервер.

```bash
# Убедитесь, что REDIS_URL в .env указывает на ваш сервер
# Запуск в режиме разработки (с hot reload)
bun run dev

# Обычный запуск
bun run start

# Сборка для продакшена
bun run build
```

## 🔧 Подключение к Telegram Business

1.  **Запустите бота.** Он должен успешно подключиться к Redis и S3.
2.  Отправьте боту команду `/start` в личные сообщения.
3.  **Настройте Telegram Business:**
    1.  Откройте **Telegram** → **Настройки** → **Business**.
    2.  Выберите **"Боты для чатов"**.
    3.  Нажмите **"Добавить бота"** и выберите вашего бота.
    4.  Подтвердите подключение.

После подключения бот пришлет вам уведомление об успешной активации.

## 📱 Использование

### Команды бота

- `/start` — запуск бота и показ инструкций.
- `/stats` — статистика работы кэша.
- `/clear` — очистка кэша сообщений в Redis.
- `/get_latest_media` — получить последний сохраненный медиафайл.
- `/help` — справка по использованию.

### Как работает отслеживание

Бот использует [Telegram Business API](https://core.telegram.org/api/business) для получения событий:

1.  **`business_message`**: Новые сообщения автоматически кэшируются в Redis на 2 минуты. Если сообщение содержит медиа, оно выгружается в ваш S3 бакет.
2.  **`edited_business_message`**: При изменении сообщения бот ищет оригинал в кэше и отправляет уведомление с показом "до" и "после".
3.  **`deleted_business_messages`**: При удалении сообщения бот ищет его в кэше. Если сообщение найдено, вы получаете уведомление с его содержимым. Если был удален медиафайл, в уведомлении будет предложена команда `/get_latest_media` для его получения.

**Важно:** События отслеживаются только для тех сообщений, которые попали в кэш (т.е. были отправлены не более 2-х минут назад).

### Примеры уведомлений

**При изменении сообщения:**

```
🔄 Иван Петров изменил(а) сообщение в чате с "Рабочий чат":

До:
> Встреча в 15:00

После:
> Встреча в 16:00
```

**При удалении сообщения c медиа:**

```
🗑️ Иван Петров удалил(а) сообщение в чате с "Рабочий чат":

Удалено:
> [Медиафайл]

🖼️ Медиафайл сохранен. Чтобы получить его, используйте команду: `/get_latest_media`
```

## 🔒 Безопасность и приватность

- **Нулевое долгосрочное хранение:** Сообщения хранятся в Redis не более 2 минут.
- **Ваш личный S3:** Медиафайлы выгружаются в ваш личный S3 бакет и автоматически удаляются через 2 минуты (или сразу после запроса).
- **Доступ только владельцу:** Только владелец бота (по `OWNER_ID`) имеет доступ к командам.

## 🚧 Ограничения

1.  **Требуется Telegram Premium** для доступа к Business API.
2.  **Требуется Redis и S3-хранилище.**
3.  **Кэш ограничен по времени** — сообщения старше 2 минут не отслеживаются.
4.  **Сохраняемые медиа** — бот сохраняет только фото, видео, голосовые и видеосообщения. Другие типы файлов (документы, стикеры) будут проигнорированы.

## 🐛 Устранение неполадок

- **Бот не отвечает:** Проверьте `BOT_TOKEN` и `OWNER_ID` в `.env`. Проверьте логи на ошибки подключения к Redis или S3.
- **Не приходят уведомления:** Убедитесь, что бот подключен в настройках Telegram Business и у вас активен Premium. Включите `DEV_MODE=true` в `.env` для подробных логов.
- **Ошибки при запуске:** Проверьте версию `bun --version`. Переустановите зависимости: `rm -rf node_modules bun.lockb && bun install`.
