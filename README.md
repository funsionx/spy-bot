# Dialog Spy Bot 🕵️

**Dialog Spy Bot** — это Telegram-бот для отслеживания изменений и удалений сообщений в ваших личных чатах через Telegram Business API. Бот работает по принципу "нулевого хранения" — не сохраняет сообщения в базу данных, а отправляет уведомления только в ваш личный чат с ботом.

## 🚀 Возможности

- ✅ **Отслеживание изменений сообщений** — получайте уведомления о редактированных сообщениях с показом старого и нового текста
- ✅ **Отслеживание удаленных сообщений** — узнавайте, какие сообщения были удалены из ваших чатов
- ✅ **Поддержка множественных удалений** — группировка нескольких удаленных сообщений в одном уведомлении
- ✅ **Краткосрочное кэширование** — сообщения хранятся в памяти только 2 минуты для отслеживания изменений
- ✅ **Безопасность** — принцип stateless, никакие данные не сохраняются после обработки
- ✅ **Форматированные уведомления** — красивые уведомления с поддержкой Markdown

## 🛠️ Технический стек

- **Runtime:** Bun
- **Язык:** TypeScript
- **Framework:** Telegraf.js
- **API:** Telegram Business API
- **Кэширование:** node-cache (in-memory) / Redis (опционально)

## 📋 Требования

1. **Telegram Premium** подписка (для доступа к Telegram Business)
2. **Bun** v1.0.0 или выше
3. **Node.js** (для совместимости с некоторыми пакетами)

## ⚙️ Установка и настройка

### 1. Клонирование репозитория

```bash
git clone <your-repository-url>
cd dialog-spy-bot
```

### 2. Установка зависимостей

```bash
bun install
```

### 3. Создание бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram
2. Отправьте команду `/newbot`
3. Следуйте инструкциям для создания бота
4. Скопируйте полученный **токен бота**

### 4. Получение вашего Telegram ID

1. Откройте [@userinfobot](https://t.me/userinfobot) в Telegram
2. Отправьте любое сообщение
3. Скопируйте ваш **User ID**

### 5. Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```bash
cp .env.example .env
```

Отредактируйте файл `.env`:

```env
# Токен вашего Telegram бота (получите у @BotFather)
BOT_TOKEN=your_bot_token_here

# ID владельца бота (ваш Telegram ID)
OWNER_ID=your_telegram_id_here

# Тип кэша: memory (node-cache) или redis
CACHE_TYPE=memory

# Настройки кэширования (в секундах, по умолчанию 120)
CACHE_TTL=120

# Redis URL (для CACHE_TYPE=redis)
REDIS_URL=redis://localhost:6379

# Пароль Redis (для docker-compose)
REDIS_PASSWORD=mypassword

# Режим разработки (true/false) - включает дополнительное логирование событий
DEV_MODE=false
```

### 🗄️ Типы кэширования

**Memory Cache (по умолчанию):**

- Использует `node-cache` для кэширования в памяти
- Подходит для разработки и небольших нагрузок
- Данные теряются при перезапуске

**Redis Cache:**

- Использует Redis для персистентного кэширования
- Подходит для продакшена и высоких нагрузок
- Данные сохраняются между перезапусками
- Поддержка кластеризации

### 6. Компиляция и запуск

```bash
# Проверка типов
bun run type-check

# Запуск в режиме разработки (с hot reload и memory cache)
export CACHE_TYPE=memory
bun run dev

# Обычный запуск с memory cache
bun run start

# Запуск с Redis
export CACHE_TYPE=redis
export REDIS_URL=redis://localhost:6379
bun run start

# Сборка для продакшена
bun run build
```

### 🐳 Docker Compose

Для запуска с Redis в Docker:

```bash
# Создайте файл .env с переменными
cp .env.example .env

# Запуск с Redis
docker-compose up -d

# Просмотр логов
docker-compose logs -f app

# Остановка
docker-compose down
```

**Структура Docker:**

- `redis` - Redis сервер для кэширования
- `app` - Приложение Dialog Spy Bot
- Автоматическое переключение на Redis в режиме `CACHE_TYPE=redis`

## 🔧 Подключение к Telegram Business

### Шаг 1: Запустите бота

После запуска бота отправьте ему команду `/start` в личные сообщения.

### Шаг 2: Настройте Telegram Business

1. Откройте **Telegram** → **Настройки** → **Business**
2. Выберите **"Боты для чатов"**
3. Нажмите **"Добавить бота"**
4. Найдите и выберите вашего бота
5. Подтвердите подключение

### Шаг 3: Проверьте подключение

После подключения бот отправит вам уведомление о successful подключении Business API.

## 📱 Использование

### Команды бота

- `/start` — запуск бота и показ инструкций
- `/stats` — статистика работы бота (количество сообщений в кэше, попадания/промахи)
- `/clear` — очистка кэша сообщений
- `/help` — справка по использованию

### Как работает отслеживание

Бот использует [Telegram Business API](https://core.telegram.org/api/business) для получения трех типов событий:

1. **`business_message`** — новые сообщения автоматически кэшируются на 2 минуты
2. **`edited_business_message`** — при изменении сообщения бот ищет оригинал в кэше и отправляет уведомление с показом старого и нового текста
3. **`deleted_business_messages`** — при удалении сообщения бот ищет его в кэше и отправляет уведомление с показом удаленного текста

**Важно:** События `edited_business_message` и `deleted_business_messages` приходят только для сообщений, которые были кэшированы (то есть пришли как `business_message` в течение последних 2 минут).

### Примеры уведомлений

**При изменении сообщения:**

```
🔄 Иван Петров (@ivan_petrov) изменил(а) сообщение в чате "Рабочий чат":

Old:
> Встреча в 15:00

New:
> Встреча в 16:00
```

**При удалении сообщения:**

```
🗑️ Иван Петров (@ivan_petrov) удалил(а) сообщение в чате "Рабочий чат":

Deleted:
> Это сообщение было удалено
```

## 🔒 Безопасность и приватность

- **Нулевое хранение:** Сообщения не сохраняются в базу данных
- **Краткосрочный кэш:** Сообщения хранятся в памяти максимум 2 минуты
- **Локальная обработка:** Все обработки происходят в памяти приложения
- **Доступ только владельцу:** Только владелец бота (по OWNER_ID) имеет доступ к функциям

## 🚧 Ограничения

1. **Требуется Telegram Premium** для доступа к Business API
2. **Кэш ограничен по времени** — сообщения старше 2 минут не отслеживаются
3. **Только текстовые сообщения** — медиа-файлы не обрабатываются (будет показано "[Сообщение без текста]")
4. **Перезапуск очищает кэш** — при перезапуске бота кэш сбрасывается

## 🐛 Устранение неполадок

### Бот не отвечает на команды

- Проверьте правильность BOT_TOKEN в файле .env
- Убедитесь, что бот запущен и нет ошибок в консоли

### Не приходят уведомления об изменениях

- Убедитесь, что бот подключен в настройках Telegram Business
- Проверьте, что у вас есть Telegram Premium
- Убедитесь, что сообщения изменяются/удаляются в течение 2 минут после отправки
- Включите режим отладки в .env файле: `DEV_MODE=true` для отслеживания событий

### Ошибки при запуске

- Проверьте версию Bun: `bun --version`
- Переустановите зависимости: `rm -rf node_modules bun.lockb && bun install`
- Проверьте синтаксис файла .env

### Проблемы с форматированием уведомлений

- Бот автоматически пытается отправить сообщение без Markdown при ошибках форматирования
- Проверьте логи в консоли для диагностики

## 📚 API Reference

### Структура проекта

```
src/
├── handlers/                 # Обработчики событий
│   ├── messageEditHandler.ts   # Обработка изменений сообщений
│   └── messageDeleteHandler.ts # Обработка удалений сообщений
├── services/                 # Сервисы
│   ├── messageCache.ts         # Кэширование сообщений
```

- **`DialogSpyBot`** — главный класс приложения

- **`MessageEditHandler`** — обработчик изменений сообщений
- **`MessageDeleteHandler`** — обработчик удалений сообщений
- **`NotificationService`** — статический класс для форматирования уведомлений
